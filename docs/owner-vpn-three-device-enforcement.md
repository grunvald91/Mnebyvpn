# Три устройства в пакете «3 в 1»: фактический аудит и этапы внедрения

## Проверенные ограничения production, 21.11.2026

Источник: https://github.com/grunvald91/telegram-proxy-infra/actions/runs/44913487041

- bundle_30d_3device: активен, 30 дней, device_limit=3.
- В реестре личных продаж на момент проверки — 0 записей.
- В entitlements установлен UNIQUE(source_order_id,product). Личная продажа создаёт одну VPN-подписку и одну Smart DNS.
- В vpn_awg_peer_allocations действует PRIMARY KEY (node_id,entitlement_id): не более одного AWG peer данного entitlement на одном сервере.
- Подписка /sub/<token> возвращает одну детерминированную приватную AWG-конфигурацию на entitlement. Её копирование на другие устройства не создаёт новый peer.
- Поэтому device_limit=3 пока является условием тарифа, **а не доказанным техническим ограничением на три физических устройства**.

## Этап 1: отдельный реестр слотов без выдачи новых ключей

Миграция 0142 добавляет закрытую таблицу owner_vpn_device_seats. В транзакции оформления одной оплаченной личной продажи создаются ровно три пустых места (1, 2, 3). Повторная операция не добавляет мест; четвёртый номер отвергается на уровне PostgreSQL. Ключи пока NULL, статус EMPTY. Публичный сайт не может записывать в таблицу. Само создание слотов **не подключает AWG и не позволяет заявлять об ограничении числа подключённых устройств**.

## Этап 2: обязательные изменения для фактического ограничения

1. Для каждого слота — отдельная клиентская пара X25519, уникальный AWG peer и адрес на каждом разрешённом узле. Приватный ключ клиента не передаётся на сервер.
2. Версионировать схему IPAM, outbox и nodekit: текущие ключи (node_id,entitlement_id) не допускают три peer одного заказа. Не менять действующие настройки до проверенного перехода.
3. Добавить защищённую регистрацию и перевыпуск: брать device_limit из неизменяемых order_terms, транзакционно блокировать слот, отклонять четвёртый ключ и гонки запросов.
4. Отдавать персональную AWG-конфигурацию только после подписанного ACK сервера. Для замены и окончания подписки отзывать соответствующий peer на всех узлах, дожидаться подтверждения.
5. Провести disposable PG/Nodekit/E2E испытания для 1/2/3/4 устройств, конкурентной регистрации, повтора, истечения, возврата и восстановления worker. Покупателям без Telegram /start понадобится отдельная защищённая первичная активация.
6. Включать эту схему сначала только для manual_sale и не изменять публичные тарифы.

Физическую уникальность устройства нельзя доказать только по X25519 ключу: один скопированный клиентский ключ может использоваться на другом устройстве. Практическая управляемая граница — максимум три независимо авторизованных peer. Нужно предотвращать распространение приватных конфигураций или честно оговаривать это ограничение.

**Важно:** 0142 сама не активирует три AWG peer. Пока этап 2 не завершён и не проверен на реальном клиенте, выдавать техническое соблюдение «до трёх устройств» за установленный факт нельзя.
