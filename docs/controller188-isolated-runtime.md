# RU188: изолированная Node.js-среда регистрации FI (этап: без сети и ключей)

Дата: 2026-11-18. **Центральный контроллер уже на `188.120.254.223`**.
Отдельный VPS для контроллера не создаём.

Проверено <https://github.com/grunvald91/telegram-proxy-infra/actions/runs/44300711843>:
хост 188 имеет Docker и SSH, но не имеет `node` в хостовой ОС;
существующие контейнеры MNEBYVPN работают на Node.js `v22.16.0`,
но не имеют `ssh`.

## Что делает эта задача

`ops/controller188-runtime/Dockerfile` создаёт **отдельный**
проверяемый контейнер из локального *immutable image ID* работающего
MNEBYVPN-сайта на 188. Alpine/Node22.16.0 и существующий `pg`
переиспользуются, внутри нового образа добавляется только OpenSSH-client.
Сайт, Telegram-бот и их конфигурации не копируются в итоговый образ;
добавляются только два entrypoint и зависимости FI/AWG.

`ops/controller188-runtime/stage.sh` требует root на 188, реально
работающие контейнеры базы и сайта, существующий
`/root/mnebyvpn-controller/bootstrap-manifest.json`, неизменяемый
образ `sha256:<64>` и изолированный каталог проверенного исходного кода.

**Единственный исполняемый режим на этом этапе** — Docker canary без
доступа к сети (`--network none`), без монтирования любых
приватных ключей/БД, без Docker socket и с `--read-only`,
`--cap-drop ALL`, `--security-opt no-new-privileges`,
ограничением памяти, CPU и числа процессов. Внутри автоматически
проверяется импорт действительных TS-модулей регистратора и
AWG-worker, доступность `pg` и SSH-клиента. Контейнер работает
однократно (`--rm`), не открывает порты и не запускает воркеры.
Новый Docker-образ остаётся как *кандидат* — не production-релиз.

## После отдельного подтверждения

Следующий технический этап: изолировать запуск уже **рабочего**
регистратора с pin SSH host key FI, ограниченной БД и
root-only ключом на 188. Тогда понадобится режим с доступом к
PostgreSQL и FI, отдельные учётные данные узко привилегированного
enrollment-роли, принудительная SSH-команда на FI и
защита от утечки ключа из контейнера. До отдельного ревью
**не монтировать `/root/mnebyvpn-controller` в этот образ**
и не использовать его с `--network host`.

Ещё дальше — AWG отдельный delivery SSH-ключ, подписанные
personal grants и проверка их отзыва; Smart DNS entitlement;
**Telegram MTProxy/Telemt** на 89 (отдельный local API:
`127.0.0.1:9096`, не аналог Smart DNS SNI).
Никаких общих неперсональных ссылок.

Существующие контейнеры и маршруты 188/89 не меняются этой задачей.
