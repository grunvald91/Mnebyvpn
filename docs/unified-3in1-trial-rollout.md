# Unified 24-hour 3-in-1 trial

Owner decision (2026-11-26): one new free offer, VPN + Smart DNS for 24h and existing common Telegram Proxy links with no trial expiration. DE/FI VPN and Smart DNS, one concurrent VPN connection across regions (owner update 2026-11-28); switching DE/FI does not renew the trial. No changes to paid pricing, no new per-customer proxy credentials. Existing trial/paid orders are not extended or reissued.

These new rows are dormant until the bundle offer is enabled and the updated worker claims them. The worker preserves explicitly selected bundle requests even when the offer is disabled; existing WAITING requests remain tied to their actual grant.
- Ready mail is selected from the actual canonical order only after both final VPN/DNS acknowledgements for bundles. SMTP acceptance is not proof of inbox delivery. The ready notice uses a stable order-derived delivery nonce and a durable gateway acceptance marker. A retry with the identical signed payload confirms recorded SMTP acceptance without another send. A crash before the acceptance marker or an ambiguous SMTP failure remains unconfirmed, never automatically resent; review these cases separately before the trial expires. This is not an exactly-once inbox delivery guarantee.

## Release gate: do not enable the offer on code-only evidence

- Both repository heads must pass CI; deploy and verify the backward-compatible ServGo gateway first.
- Apply migrations 0160–0165 before restarting upgraded workers; verify the running provisioning and expiry workers can execute the new observed acknowledgement under their actual restricted roles. Keep the existing offer flags unchanged during this rollout.
- Verify actual enforcement of 30,000 requests per trial across both countries, including cache hits; country switching must not reset the counter. The 1 GiB value in test fixtures is not a production quota. Migration 0163 sets 30,000 on newly issued canonical bundle trial DNS credentials, using the existing shared DE/FI reservation meter. The current meter settles successful mapped DNS answers, including upstream-cache hits; ordinary direct DNS lookups bypass it. Migration 0164 and the updated DE listener implement trial-only strict accounting for successful direct and mapped DNS replies (including cache hits) and deny unmetered trial fallback during controller outage, expiry or quota exhaustion. Migration 0165 emits the cryptographically bound ACTIVE_TRIAL grant state for canonical internal bundle trials. Companion FI implementation: https://github.com/grunvald91/telegram-proxy-infra/pull/550. Upgrade the FI snapshot validators and customer runtime before publishing any ACTIVE_TRIAL grant; old validators reject that state (and can reject a mixed snapshot), while legacy passthrough continues to reject trial access. Ensure no existing bundle trial has already been published as legacy ACTIVE before rollout. Run the pinned companion policy/build contracts and actual cross-region trial tests before enabling the offer. Paid and legacy standalone profiles retain the original ACTIVE state. Do not enable the offer until both regions and controller are deployed and verified. Failed/no-answer requests release their holds; this is a successful-answer quota, not an attempted-packet counter. Verify this metric against owner policy. The DE runtime must have EXECUTE on personal_dns_meter_policy(text) before restart; the migration copies explicit existing recognition grants, and startup probes the new function. Existing issued credentials are not migrated; verify no historical bundle trial credentials need reconciliation before enabling.
- Verify an actual newly issued test account: Germany and Finland VPN/Smart DNS links, a single canonical 24-hour deadline, both final acknowledgements, common proxy links and correct email.
- Verify **actual** admission on both VPN data planes: one simultaneous connection in either country, second denied on both same and other node, slot released and reusable in the other country, expiry and loss of controller contact deny new and established traffic. The SQL claim gate alone is insufficient. The shared admission flag is intentionally not enabled by this PR.
- Verify expiry on live nodes, not just the database: Germany and Finland DNS credential denial and VPN session termination. The shared HTTPS relay is not a per-user entitlement gate; do not claim revocation of generic HTTPS reachability on a previously learned relay IP. Telegram common proxy stays usable.
- Verify that purchasing a paid bundle creates a separate subscription; this branch does not promise reuse of expired trial credentials.
- Only after these gates pass, switch to the bundle-only offer with the validated DNS allowance. Confirm public catalog and new website/Telegram/email recovery requests use it. Verify counts without exporting customer addresses or credentials. Keep a rollback path for offer flags and workers.
