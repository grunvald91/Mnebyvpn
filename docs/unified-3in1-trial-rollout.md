# Unified 24-hour 3-in-1 trial

Owner decision (2026-11-26): one new free offer, VPN + Smart DNS for 24h and existing common Telegram Proxy links with no trial expiration. DE/FI VPN and Smart DNS, one concurrent VPN connection across regions (owner update 2026-11-28); switching DE/FI does not renew the trial. No changes to paid pricing, no new per-customer proxy credentials. Existing trial/paid orders are not extended or reissued.

7. Expiry/renewal: revoke VPN/DNS at canonical deadline; common Telegram Proxy unaffected. Verify expired link denial and no changes to paid orders; evaluate credential retention when purchasing a bundle rather than promise it unconditionally.
8. Release: migration and unit/integration tests; verify one order/two entitlements, parallel claims, historical cohort, referral continuity, denied second connection across nodes, no premature activation, expired credentials, proxy link still valid, renewal regression. Require live server checks before enabling bundle-only trial offer and deployment verification after CI/merge.

## Release gate: do not enable the offer on code-only evidence

The 1 GiB value in test fixtures is not a production quota. Migration 0163 sets 30,000 on newly issued canonical bundle trial DNS credentials, using the existing shared DE/FI reservation meter. The current meter settles successful mapped DNS answers, including upstream-cache hits; ordinary direct DNS lookups bypass it. Migration 0164 and the updated DE listener implement trial-only strict accounting for successful direct and mapped DNS replies (including cache hits) and deny unmetered trial fallback during controller outage, expiry or quota exhaustion. Run the pinned companion policy/build contracts and actual cross-region trial tests before enabling the offer. Paid and legacy standalone profiles retain the original ACTIVE state. Do not enable the offer until both regions and controller are deployed and verified. Failed/no-answer requests release their holds; this is a successful-answer quota, not an attempted-packet counter. ### Automatic issuance and recovery (stage 6)

- Migration 0167 adds a second idempotent one-time historical cohort snapshot: verified-email accounts with no prior grant, access or device claim, and existing unexpired/pending canonical bundle grants missing a recovery queue. Review accounts and existing queue records are excluded. Ungranted legacy email requests (including pre-existing pending recovery records) are parked with requested_product=bundle and next_attempt_at=infinity until the bundle offer is explicitly enabled. Missing notices for existing canonical bundle grants enter WAITING with their original order ID and can be sent even while new grants are disabled. Drain the old recovery worker before migration 0167; a worker that already claimed a row must finish before migration. Existing grants retain their original order, activation and expiry; no replacement or extension is performed. Previously expired or VPN-only grants are not automatically converted.
- Explicit bundle requests are preserved even while the offer is disabled. A new email bundle is not directly granted when the durable ready-notice queue cannot be written. Worker claims persist the bundle choice before attempting the grant, preventing downgrade on retry. Mail readiness requires the canonical order, matching 24h period and both final node acknowledgements; the worker rechecks its lease before sending.
- Telegram ready notification links directly to the trial country menus rather than the generic newest-subscription DNS action; it includes the trial DNS quota.
- ServGo gateway PR 171 is merged, but live gateway availability and delivery behavior must still be verified. Verify counts of historical eligible accounts, outstanding grants, duplicate avoidance, readiness and actual SMTP acceptance on production before enabling; no real email has been sent by this stage. A previously rejected queue is not silently reopened; inspect rejection reasons separately, especially device reuse and expired grants.
