# MNEBYDNS — личное меню доменов в @MNEBYVPN_bot

Статус: запросы владельца через Telegram, **не автоактивация DNS**.

## Доступ
Только Telegram private chat, подтверждённый подписанным webhook:
- При наличии `DNS_ADMIN_TELEGRAM_ID` только этот числовой Telegram ID.
- Если переменная отсутствует, используется действующий `SUPPORT_TELEGRAM_OPERATOR_ID`.
- Если соответствующий ID невалиден или отсутствует, меню не показывается.
- Имя @username не даёт полномочий; перенаправленные callback или групповое сообщение не принимаются.

**Нельзя** открывать публичную настройку ID, выдавать полномочия по имени
пользователя или использовать внешние bot-token ответы без проверки webhook.

## Кнопки
1. **🛠 Управление Smart DNS** на главной (видна лишь владельцу).
2. **➕ Добавить домен** — запросить ответ на сообщение. Только
   доменное имя: `oracle.com`; не URL, не IP, не `*.example.com`, не локальный домен.
3. **📋 Домены и статусы** — последние 15 зарегистрированных запросов.
4. **☁️ Oracle** — внести `oracle.com` и `cloud.oracle.com`.
   Эти кандидаты автоматически добавлены миграцией 0108 с `PENDING`.
5. Открыть карточку домена и отменить заявку; ACTIVE создаёт заявку на отключение,
   но не отключает действующий прокси без внешнего подтверждения.

## Статус каждого запроса
- `PENDING` — только заявка, **ни один реальный сервер не изменён**.
- `FAILED` — проверка не пройдена.
- `ACTIVE` — зарезервировано для проверенного отдельного DNS-применения.
- `CANCELLED` — отменён запрос; никакой сетевой конфигурации не изменено.
- `REMOVAL_PENDING` — требуется проверенное отключение правила на сервере.

Данные хранятся в `dns_admin_domains` через параметризованный SQL.
Таблица создаётся миграцией `0108_dns_admin_domains.sql`. На каждый домен одна
строка: повторная доставка Telegram webhook идемпотентна.

## Важное для будущего рабочего DNS-применения
Не использовать содержимое очереди как автоматическую конфигурацию Nginx.
Отдельный контроллер должен предварительно проверить:
- публичный DNS и все RR-типы A/AAAA/HTTPS/SVCB/CNAME, DNSSEC;
- реальный TLS/QUIC к оригинальному origin с верификацией сертификата;
- независимый внешний egress, защиту от DNS rebinding и приватных IP;
- готовность SNI/HTTP3 прокси (TCP+UDP) и клиентский тест на Android;
- сохранность уже работающих Gemini/Claude/Grok/X/TikTok;
- снимок, атомарную проверку nginx/DoT, независимый rollback-таймер;
- подтверждённый post-apply health перед переходом записи в `ACTIVE`.

Один DNS hostname **не гарантирует** работоспособность службы.
Случай Threads показывает, что реальная маршрутизация приложения может
использовать другие домены и транспорт, а выбор HTTP/3 нельзя навязать DNS.
Для включения Oracle через Smart DNS сначала подтвердить целевой продукт:
OCI Console (`cloud.oracle.com`) или основной сайт (`oracle.com`).
