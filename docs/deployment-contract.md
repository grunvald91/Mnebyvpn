# Deployment contract: сеть, порты, имена, версии

**Контракт для будущей реализации; текущая конфигурация серверов не изменялась.**

## Имена: пока зарезервированы логически, НЕ зарегистрированы

| Функция | Условный DNS-адрес | Доступ |
|---|---|---|
| Клиентская VPN подписка | `sub.<наш-домен>` | HTTPS клиенту |
| Telegram bot webhook / коммерческий API | `api.<наш-домен>` | HTTPS, аутентификация |
| Remnawave панель | `panel.<наш-домен>` | закрытый админ-контур |
| Персональный DNS-over-HTTPS | `dns.<наш-домен>` | HTTPS DoH с отдельно выбранной схемой авторизации |
| Smart DNS client setup | `connect.<наш-домен>` | HTTPS настройка и инструкции |
| Мониторинг | `ops.<наш-домен>` | закрыто, не публичная панель |

Конкретный домен и доступность имён **не подтверждены**. Не хардкодить IP сервера в публичной клиентской ссылке. Подписочный endpoint должен поддерживать перенос: TTL, DNS, reverse-proxy, сертификаты, токены и откат. Remnawave требует корректного размещения origin; проверять reverse proxy по официальным инструкциям, **не считать** что произвольный URL path поддерживается.

## Портовый контракт перед запуском

1. Собрать из живой системы все `ss -lntup`, nginx `stream` SNI maps, upstream, NAT, docker `ports`, WireGuard и условия firewall.
2. На зарубежном VPS *уже занят* публичный 443 и внутренний 8443 (Xray). На российском *занят* 443/80 и несколько публичных прокси-портов.
3. Remnawave Node использует host networking в официальном docker-compose примере; он **не изолирует** конфликты портов от хостовой ОС.
4. Новым Node, DNS resolver и SNI ingress сначала выделить отдельные тестовые порты и пути в изолированной среде. Нельзя отнимать 443 у существующего nginx.
5. Для публичного Smart DNS TCP passthrough на 443 требуется **отдельный IP или согласованное SNI-мультиплексирование** текущего stream-proxy; просто добавить отдельный контейнер :443 на том же IP нельзя.
6. DoH обслуживается на HTTPS 443 под своим именем через согласованный TLS reverse proxy; DoT 853 — отдельный протокол и порт, если открыт/поддерживается. Публикация обеих технологий требует теста аутентификации и раздельной политики доступа.
7. Node control API порт должен приниматься только от панели; панель/API/метрики защищены, а не доступны любому.

## Version & contract manifest (создать перед установкой)

`upstream-versions.lock` должен фиксировать backend tag/OCI digest, node tag/digest, Xray version, контракт SDK, CoreDNS/nginx версии, совместимость DB/Redis и миграции. Пример без боевых версий пока не создаём.

## Preflight gates

- Достаточная RAM/CPU/диск на ru-edge **после согласованного resize**.
- Live port map и маршруты подтверждены; TLS SNI routing проверен в тесте.
- Все клиентские домены и сертификаты доступны/управляемы нами.
- Зашифрованный backup и восстановление подтверждены.
- Проверены правила firewall, нет неаутентифицированных open proxy, не используются ключи из Git.
- Провайдер VPS/Cloud API поддерживает будущие автоматизированные операции, но API токены не выданы ИИ.
