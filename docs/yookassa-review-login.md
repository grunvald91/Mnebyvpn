# ЮKassa: постоянный тестовый вход

Реализация PR #148. Публичный логин: https://mnebyvpn.site/#account («Мой VPN»).

## Поведение

- **Только одна** строка `web_review_login(singleton=true)`, с существующим `accounts.id` и без административных прав.
- Для указанного адреса `POST /api/auth/email/start` **не отправляет письмо**, возвращает `REVIEW_CODE_REQUIRED`. Существующая форма становится восьмизначной. Другие email используют прежний одноразовый шестизначный код.
- Верификация server-side, `scrypt(N=16384,r=8,p=1)` с 128-битной солью и секретом `WEB_SESSION_SECRET`; время выполнения проверки не является токеном доступа.
- Максимум 10 проверок за час для reviewer-email, 80 за час с IP, блокировка на 30 минут после 5 неверных попыток. Есть отдельный лимит запросов начального экрана.
- Успех выдаёт **обычную** revocable `website_sessions` сесссию на 12 часов; аккаунт не истекает. Отключение немедленно отклоняет имеющиеся сессии.
- Reviewer не может привязывать к тестовой записи Telegram или другой email.

## Провижининг (только доверенная среда, не CI-логи)

1. Проверить успешный CI, применённую миграцию `0123_yookassa_review_login.sql` в **канонической БД** и права роли `mnebyvpn_site_auth` (SELECT + UPDATE только `failed_attempts`, `locked_until`). До миграции **не публиковать** новый сервер: запросы `/api/me` используют новую таблицу.
2. В привилегированной операционной среде проекта установить `DATABASE_URL` **для владельца канонической БД**, `WEB_SESSION_SECRET` **из того же реального сайта**, `REVIEW_LOGIN_EMAIL`, `REVIEW_LOGIN_CODE`. Все значения загружаются из закрытого секретного хранилища или защищённого интерактивного ввода. Не вводить восьмизначный код в аргументах, URL, GitHub Actions workflow_dispatch input, PR, задачи, логи или публичный shell history.
3. Выполнить `node --experimental-strip-types ops/manage-review-login.ts provision` с применённой миграцией. Команда не печатает секрет, создаёт или обновляет **один** аккаунт, меняет хеш, отзывает предыдущие сессии.
4. В реальном браузере проверить `/#account` → тестовый email → «Получить код» → постоянный код → кабинет. Повторить в другом браузере. Проверить обычный email и неверный код.
5. Только после подтверждения живого входа передать сотрудникам ЮKassa email и код **через защищённый канал**.

Отключение: `node --experimental-strip-types ops/manage-review-login.ts disable` в той же привилегированной среде. Команда отмечает `enabled=false`, отзывает ранее выданные сессии, не удаляя аккаунт и платежи. Для смены кода повторить `provision`.

**Важно:** при смене `WEB_SESSION_SECRET` прежний хеш постоянного кода не подойдёт; после ротации необходимо повторное закрытое provision. Тестовый пользователь не получает оплаченных услуг, пока платёж не подтверждён существующим механизмом. Не включать test auto-capture или административные роли.

**Граница работы:** установка кода/почты — отдельный приватный операционный шаг, не выполнимый через публичный PR. Не считать задачу завершённой, пока нет живой проверки и передачи реквизитов.
