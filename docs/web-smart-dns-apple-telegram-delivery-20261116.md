# Покупка Smart DNS: Apple-профиль и Telegram-прокси

Дата реализации: 2026-11-16. Статус: код подготовлен в PR, **не развёрнут**.
Выдача профиля и Telegram-бонус не должны активироваться до реального DoT/Telemt E2E.

## Apple (iPhone, iPad, Mac)

После подтверждённой оплаты и ACTIVE-статуса DNS-сервера личный кабинет предлагает
«Скачать профиль iPhone / iPad / Mac»; то же действие доступно из карточки
«Оплата подтверждена». Браузер получает **персональный** файл
`MNEBYDNS-Apple.mobileconfig` (DNS-over-TLS, только DNS Settings payload).
Для установки: Safari → скачать → системные настройки → загрузить/установить профиль;
на Mac открыть скачанный .mobileconfig и подтвердить в «Профили».
Сертификат DoT-сервера обязан быть доверенным и покрывать персональные hostnames.

Выпуск защищён авторизованной сессией, CSRF, оплаченной транзакцией,
ACTIVE smart_dns entitlement и атомарной SQL-функцией с проверкой владельца.
Сайт/БД не сохраняют открытый hostname, только SHA-256. Повторное скачивание
невозможно без **явной ротации**: старые Apple и Android конфигурации перестают
действовать. Файл нельзя пересылать, включать в логи и публичный кэш.
Сайт отдаёт no-store, attachment MIME и X-Robots-Tag noindex.
Пробный, неоплаченный, истекший, возвращённый и чужой доступ не дают файл.

SQL: `db/migrations/0125_website_personal_dns_apple.sql`.
Выполнять **после** миграции 0120, без ручной раздачи прав PUBLIC.
Для production с отдельной `mnebyvpn_site_auth` ролью — убедиться в GRANT EXECUTE.

Выдача отключена без обоих флагов:
`WEB_PERSONAL_DNS_APPLE_ENABLED=yes`,
`WEB_PERSONAL_DNS_DOT_E2E_VERIFIED=yes`
и существующего `WEB_NETWORK_PROVISIONING_VERIFIED=yes`.
Нельзя включать на основании CI без проверки на физических устройствах.

## Telegram (iPhone, iPad, Mac, Android, Desktop)

В карточке оплаченного ACTIVE smart_dns после подтверждённой серверной
выдачи доступны **два маршрута** Telemt direct-ozon с одним личным секретом:
89.125.90.101:9446 и 188.120.254.223:8443 (через RU WG к тому же
Telemt-профилю). Настройки DNS и прокси существуют параллельно: 
Smart DNS остаётся включён, **только Telegram** использует MTProxy.
Ссылка открывает Telegram; если t.me недоступен, клиент копирует host/port/secret
и добавляет MTProto в настройках Telegram. Звонки через MTProto могут не работать.

`GET /api/telegram-proxy-bonus` уже ограничен владельцем PAID/ACTIVE и не выдаёт
секрет без записи `dns_mtproxy_bonus_credentials` с проверенным ACTIVE состоянием.
Перед включением обязательны: Telemt per-entitlement provisioner, подтверждённый
автоматический disable при expiry/refund, проверка двух маршрутов на iPhone и
сверка использования **одного** Telemt direct-ozon, НЕ rf-media.
Флаги: см. `docs/dns-telegram-proxy-bonus-20261112.md`.
Если бонус не готов, сайт не должен показывать фальшивую рабочую ссылку.

## Не сделано автоматически

Эта PR не включает DNS-продажи, не меняет порты/DNS/WireGuard/Telemt на серверах,
не создает пользователей Telemt и не выдаёт себе статус реального E2E.
Чтобы продавать DNS и обещать бонус **каждому**, отдельно нужен испытанный
Telemt worker с персональным созданием и отзывом; включать раздачу без этого нельзя.
