# Автоматический отчёт Google Search Console — MNEBYVPN

## Назначение

Еженедельный отчёт по органическому поиску для `mnebyvpn.site`: 28 завершённых дней по времени Google Search Console (Pacific Time) и предыдущие 28 дней; клики, показы, CTR, средняя позиция; все восемь канонических URL (главная и семь инструкций); индексация через Google URL Inspection; группы запросов по доступной выборке.

Плановое расписание: понедельник, 05:37 UTC. Отправка **в приватный Telegram**, а не в общедоступные логи GitHub. Отчёт не содержит полных поисковых фраз, персональных DNS-ссылок или токенов. Google может анонимизировать запросы и возвращать только верхние строки, поэтому это **не** полноценная рыночная частотность.

**Точность выборки:** восемь отслеживаемых URL выбираются через один поддерживаемый Search Analytics фильтр `page` с оператором `includingRegex` и якорями начала/конца. Google документирует `filterLists` для стран и устройств, поэтому его для страниц не применяем. Общие показатели по свойству считаются отдельно; при доменном свойстве они могут включать поддомены. Поисковые фразы используются для группировки, но сами не выводятся в Telegram или GitHub.

**Рекомендации в отчёте — проверяемые эвристики, а не автоматическое SEO-редактирование:** отдельно помечаются ошибки URL Inspection, снижение показов более чем на 50% при не менее 40 показах ранее и CTR ниже 1% при не менее 100 текущих показах. Для каждой подсказки выводится основание в цифрах. Эти сигналы не доказывают конкретную причину и не обещают рост позиций. Отсутствие показов не доказывает отсутствие индексации. URL Inspection возвращает статус версии в индексе, а не проверку живого URL.

## Текущее состояние

Рабочий код и офлайн-тесты подготовлены. **Отдельный флаг ручного включения удалён:** после изменения workflow на `main` выполняется однократная автоматическая попытка, далее — по понедельникам. Перед обращением к Google проверяется наличие служебного JSON, существующего токена бота и ID оператора **в secrets этого репозитория**; если чего-то нет, отправка безопасно пропускается без сетевых запросов. Наличие ID в среде сервера 188 само по себе не означает наличие этого секрета в GitHub Actions другого репозитория.

### Одноразовая настройка доступа (без передачи секретов в чат)

1. В Google Cloud создать служебную учётную запись и включить *Google Search Console API*. Предоставить учётной записи доступ к свойству `sc-domain:mnebyvpn.site` в Search Console (разрешённой роли чтения достаточно для отчёта).
2. Создать JSON-ключ этой служебной учётной записи, записать **только** в Actions secret **`GSC_SERVICE_ACCOUNT_JSON`** репозитория `grunvald91/Mnebyvpn`. Никогда не добавлять JSON в коммиты, файлы или issue.
3. **Не создавать отдельный токен бота и не переносить Telegram ID.** Используется уже существующий GitHub Actions secret **`TELEGRAM_BOT_TOKEN`** (резервное имя `TELEGRAM_TOKEN_BOT`). GitHub подписывает только текст отчёта, а сайт на сервере 188 проверяет подпись и отправляет сообщение через действующий `TELEGRAM_TOKEN_BOT` владельцу с уже настроенным серверным `SUPPORT_TELEGRAM_OPERATOR_ID`. Токен и ID не передаются по сети и не публикуются в Actions. Путь доставки — только `POST /api/internal/gsc-report` с HMAC-SHA256, 120-секундным окном и защитой от повтора. Перед первым рабочим запуском требуется зелёный CI и выкладка нового веб-обработчика на 188.
4. При необходимости создать Actions variable **`GSC_SITE_URL`** (точно `sc-domain:mnebyvpn.site` или `https://mnebyvpn.site/`). По умолчанию используется `sc-domain:mnebyvpn.site`.
5. **Флаг `GSC_REPORT_ENABLED` не нужен.** После выкладки серверного обработчика переключаем workflow на два доступных секрета (`GSC_SERVICE_ACCOUNT_JSON` и существующий `TELEGRAM_BOT_TOKEN`) и автоматически проверяем живую доставку через Actions. Владелец уже разрешил еженедельную отправку. Повторного ввода ID не требуется.

Изменения в DNS, прокси, VPN, платёжной системе, личном кабинете, Search Console или состоянии сайта **не выполняются**. OAuth scope — `https://www.googleapis.com/auth/webmasters.readonly`.

## Запуск проверок без Google-ключей

```bash
npm test -- --test-name-pattern='Search Console|GSC|Telegram|topic|query|28-day|report|metrics|JWT'
npm run typecheck
```

Полный стандартный `npm test` также включает `tests/gsc-weekly-report.test.ts`.

## Почему отчёт ещё не включён

Первый запуск Actions подтвердил наличие `GSC_SERVICE_ACCOUNT_JSON` и `TELEGRAM_BOT_TOKEN`, но не нашёл `SUPPORT_TELEGRAM_OPERATOR_ID` в секретах репозитория. Поэтому добавлен защищённый сайт-релей, использующий Telegram ID **на сервере 188**, без его копирования в GitHub. Реальная доставка требует успешного релиза сайта и следующего live запуска. Проверенная Google-авторизация и вручение сообщения будут отмечены только после подтверждённого E2E.
