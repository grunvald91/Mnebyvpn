# Offline-first авторизация: RU188 управляет, узлы обслуживают трафик

**Статус:** архитектурный контракт и код фоновых AWG-обновлений. У FI пока нет завершённой доверенной регистрации и рабочего production E2E. Этот документ НЕ разрешает активацию новых публичных узлов.

## Главный принцип

1. **Control plane:** RU188 хранит подписки, оплаты, revoke/revision, инвентарь и Ed25519 private signing key. Публичные ключи обменяются при provisioning/enrollment или ротации, а НЕ при установлении клиентского соединения.
2. **Distribution plane:** отдельный RU188 worker раз в 60 секунд читает изменения оплаты/предстоящий expiry и формирует в PostgreSQL подписанные команды. Outbox доставляет их асинхронно до узла через закреплённый SSH, ожидает криптографический ACK. Краткие сбои доставки переподписываются с новой ревизией; старую ревизию узел отвергает.
3. **Data plane:** FI/другие узлы держат локальную авторизацию в защищённом состоянии. AWG проверяет локальные peer public keys/AllowedIPs, Xray — локальную подписку; никакого запроса к RU188, Postgres или REST при handshake, DNS-запросе, каждом пакете или открытии прокси-соединения.
4. **Offline:** уже авторизованный клиент подключается при недоступности RU188, пока локальное подписанное разрешение не истекло. Новый пользователь без заранее доставленного гранта не пропускается. Отмена/досрочный отзыв вступает в силу после доставки; если канал недоступен, гарантирован только локальный expiry.

## Текущая политика AWG

- Период локального гранта: `min(оплаченный expires_at, текущее время + 7 суток)`. На node требуется корректное время, контроль отката часов и локальный watchdog раз в 2 секунды.
- RU188 выбирает к продлению гранты с остатком не более **48 часов**, включая повторную выдачу после потерянного ACK (не ранее **90 секунд**, т.к. окно старой команды **40 секунд**).
- Отзывы имеют приоритет над продлениями. Состояния и ревизии обновляются транзакционно в RU188; Nodekit подтверждает реальное применение узловой подписью.
- Для cancelled/expired подписки в локальном node без связи с RU188 возможен максимум **семидневный лаг досрочного отзыва**. Это компромисс, который нельзя устранить мгновенной глобальной проверкой без потери автономности. При полном отсутствии доставки через 7 суток даже ранее оплаченному клиенту потребуется возобновление фоновой синхронизации. Период можно изменить отдельным согласованным изменением политики.
- Ни планировщик, ни delivery-worker не подключаются из клиентского HTTP, DNS или VPN-запроса; сервисы остаются отключёнными до FI enrollment, подписанного E2E, проверки отмены и release gates.

## Перенос архитектуры на остальные протоколы

- **Персональный DNS:** локальный ACL для идентификатора персонального профиля, локальный paid_until/revoked, асинхронная ревизия. Нельзя делать общий открытый резолвер или выдавать общий профиль. Если DNS-запрос попадает на RU188 как ingress, это отдельная транспортная задержка; локальный ACL устраняет именно ожидание авторизации, а не сетевые транзиты.
- **Telegram Telemt:** отдельный per-user secret и локальный реестр разрешений/expiry; загрузка revocations асинхронно, без звонка контроллеру на входящем MTProto-сеансе. Smart DNS SNI транспорт **не равен Telemt**.
- **Xray/VLESS:** уже реализован локальный supervisor с persisted clock-highwater; синхронизация entitlements остаётся отдельным доверенным процессом.
- **Секреты:** Ed25519 controller private key никогда не покидает root-only RU188, на узлы доставляется только публичный trust anchor и подписанные команды. Первое SSH-подключение использует ранее одобренную пользовательскую политику автоматического pinning на RU188, не live client traffic.

## Незакрытые пункты до боевого выпуска

FI enrollment и forced-command доступ, установки доверенных публичных ключей, проверка реального AWG/Android, push отзы́ва и E2E на устройстве, персональный DNS и Telemt offline ACL. Наличие кода фоновых обновлений не подтверждает, что эти задачи развернуты.
