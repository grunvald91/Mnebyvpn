# Runbook аварий и восстановления

**Не заменяет действующие бэкапы и не разрешает менять VPS.** Никаких восстановлений пока не выполнялось.

| Сбой | Что ожидаем | Процедура | Доказательство восстановления |
|---|---|---|---|
| ru-edge/control plane недоступен | нет новых выдач/оплат/обновлений подписок; уже работавший Xray может продолжать трафик при определённых условиях | независимый алерт → проверить infra → поднять контроль из offsite backup после разрешения | API, DB, выдача/отзыв, сертификаты, heartbeat Node |
| foreign-exit/VPN node недоступен | VPN-трафик через узел не работает | исключить подтверждённо умерший узел из выдачи, восстановить/развернуть новый с проверками | внешнее end-to-end подключение в клиенте |
| DNS resolver недоступен | Smart DNS резолвинг ломается или устройство меняет resolver | alarm, проверка DNS ответов, authorized restart или rollback только своего сервиса | DoH/DoT probe + браузерный тест |
| SNI ingress недоступен | выбранные HTTPS-сервисы недоступны даже при живом DNS | исключить неисправный маршрут, rollback DNS rewrite, не трогать старые nginx maps | HTTPS TLS сертификат валиден, исходный сайт отвечает |
| Подписочный домен/TLS недоступен | клиенты не могут импортировать/обновить VPN | DNS/TLS restore по runbook, при необходимости переключить контролируемый endpoint | HTTPS probe + импорт с реального клиента |
| Нарушение синхронизации прав | платёж есть, доступа нет или expired имеет доступ | deterministic reconciliation и audit | desired = actual для тестового пользователя |
| Компрометация/необычная активность | риск утечки ключей и подмены | freeze autoscaling/mutations, изолировать доступ, incident response под контролем владельца | восстановленные ключи/доступ, отчёт инцидента |

## Предпосылки восстановления

- Offsite зашифрованные backups: PostgreSQL, необходимые secrets, policy store DNS, инфраструктура/профили, TLS материалы, provider IaC state.
- Тестовое восстановление на изолированном тестовом окружении, секреты не передавать в публичный репозиторий.
- Чётко измерять RPO и RTO в испытаниях; текущих подтверждённых RPO/RTO **нет**.
- Предусмотреть независимый канал владельца/оповещения: Telegram может быть недоступен; нужен согласованный резервный канал.
- Контроллер и ИИ никогда не должны удалять единственный backup/систему для «восстановления».
- Rollback DNS разрешённых записей требует проверки TTL, propagation, клиентских cache, а не только смены конфигурации.

## Single points of failure

На двух VPS control plane и зарубежный exit остаются точками отказа. Для полноценной HA позже потребуются резервные экземпляры/провайдеры, DNS availability и независимый мониторинг. **Автоскейлинг не равен отказоустойчивости** и не восстанавливает потерянную БД без backup.
