# MnebyVPN — обращения в поддержку (сайт + Telegram)

## Пользовательский путь

- **Telegram-бот:** кнопка «✉️ Поддержка» или команда `/support`. Бот показывает поле ответа (ForceReply); пользователь пишет обычный текст. Команда `/support <сообщение>` также принимается. После подтверждённого Bot API `sendMessage` бот сообщает, что обращение отправлено в чат поддержки.
- **Сайт:** ссылка «Поддержка» и форма `#contact-support`. Достаточно контакта для обратной связи и описания проблемы; авторизация не нужна, поскольку сайт нужен в том числе при отсутствии доступа к Telegram. `POST /api/support` принимает JSON только с собственного origin; `GET /api/support/status` сообщает, подключён ли канал.
- **Оператор:** уведомления поступают в указанный Telegram-чат. Для обращений из бота оператор может ответить **прямым ответом** на уведомление или командой `/reply <telegram_user_id> <сообщение>`. Ответ уходит пользователю от основного бота. Для обращений с сайта оператор использует предоставленный контакт (email / Telegram username); сайт не обещает автоматической доставки ответа по email.
- **Безопасность:** не просить у клиента пароли, коды входа, ссылки подписок. Отправка обращений не меняет VPN-подписки и не запускает денежные операции.

## Настройка на обоих backend-сервисах

Прописать в защищённом окружении **и веб-сервера, и основного Telegram webhook backend**:

| Переменная | Описание |
|---|---|
| `SUPPORT_TELEGRAM_BOT_TOKEN` | Секрет Bot API токена **основного MnebyVPN-бота**, который принимает обращения и отправляет ответы. Хранить только в secret storage сервера, не в Git. |
| `SUPPORT_TELEGRAM_CHAT_ID` | Числовой ID личного чата оператора или выделенной группы. Бот должен иметь право писать в чат; оператор должен запустить диалог с ботом либо добавить его в группу. |
| `SUPPORT_TELEGRAM_OPERATOR_ID` | Числовой Telegram user ID доверенного оператора. Для группы **обязателен**, чтобы никто из других участников не мог отвечать клиентам через бота; для личного чата необязателен, если `CHAT_ID` равен ID оператора. |

Если не заданы token и chat ID, веб-форма становится неактивной, а бот честно сообщает о недоступности поддержки. Неполная/невалидная конфигурация приводит к ошибке запуска процесса.

Используется HTTPS `https://api.telegram.org/bot<TOKEN>/sendMessage` без вывода токена или текста сообщений в журналы. **Никаких секретов в публичных файлах** и никаких изменений действующих VPS в рамках этого PR. Для запуска сервер должен иметь исходящий HTTPS-доступ к Telegram Bot API.

**Важно:** хранение этого токена на веб-сервере расширяет область доступа к основному боту. До выкладки должны быть проверены права к окружению, защита сервера, разграничение доступа и возможность ротации токена. В будущем желательно вынести отправку в отдельный узкий внутренний service/relay.

## Ограничения текущего MVP

- Сообщения **не сохраняются в БД**. Доставкой считается подтверждённый `ok: true` от Telegram Bot API, а не прочтение человеком.
- Rate limit — **локальный в памяти одного процесса**: до 3 обращений на контакт / Telegram ID за 15 минут и общий лимит 120/мин на каждый backend. При нескольких экземплярах и против распределённого спама дополнительно нужен edge rate limit / антибот-контроль.
- При сетевом таймауте результат отправки может быть неопределённым; клиент видит ошибку подтверждения и может повторить. Дубликаты после перезапуска процесса теоретически возможны. Для production-SLA потребуется транзакционный outbox / dedupe и журнал обращений.
- **Не объявлять SLA «ответ за N минут»**, пока нет расписания дежурств, метрик и реальной поддержки.
- Данные формы отправляются в Telegram. Прежде чем публично принимать ПДн через сайт, опубликовать применимые юридические документы, определить сроки хранения, оператора и обработку обращений; см. `docs/commercial-readiness.md`.
- Тесты и действующие backend-сервисы не заменяют E2E проверки реального чата: сайт → оператор, бот → оператор, оператор → пользователь. До проверки считать **UNVERIFIED**.

## Ручной smoke-check перед выпуском

1. В секретах обоих сервисов настроить токен, chat ID, operator ID; проверить исходящий доступ к Bot API и отсутствие секрета в логах.
2. Открыть сайт с телефона без входа, отправить заявку с email — в чате должно прийти уведомление **с сайта**. Неправильный `Origin` должен быть отклонён.
3. В боте нажать «✉️ Поддержка», ответить обычным текстом, получить подтверждение и уведомление в операторском чате.
4. В операторском чате ответить на уведомление **из бота**. Ответ должен появиться у отправителя; чужой user ID не должен получить доступ к обращению.
5. Отключить/испортить конфигурацию в изолированной среде — не должно быть ложного «отправлено».
