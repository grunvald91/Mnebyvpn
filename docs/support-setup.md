# MNEBYVPN — поддержка в одном существующем Telegram-боте

## Без второго бота и без нового токена

Поддержка работает через тот же [@MnebyVPN_bot](https://t.me/MnebyVPN_bot), через который клиент управляет VPN, покупает доступ и проверяет подписку. Отдельный бот **не нужен**. Для обычного ответа на входящий webhook Telegram может выполнить один метод `sendMessage`; для **мгновенных уведомлений о заявках с сайта** используется приватно установленный токен этого же бота.

- Клиент: нажимает **«✉️ Поддержка»**, пишет сообщение в открывшемся поле ответа; оно направляется оператору по его личному Telegram user ID. Ручной ввод команд не нужен.
- Оператор: получает обращение с кнопкой **«✍️ Ответить клиенту»**. Нажатие открывает поле ответа; Telegram отправляет сообщение клиенту через результат существующего webhook. При желании можно отвечать через стандартное Telegram «Ответить» на сообщение.
- Отдельный `SUPPORT_TELEGRAM_CHAT_ID`, второй Telegram-бот и второй токен не требуются.
- Если исходящий Bot API доступен, ответ клиенту отправляется напрямую, а подтверждение API проверяется. Если бот работает без токена в runtime, он использует один метод в ответе на webhook; такой ответ сам по себе **не является** подтверждением доставки.

## Обращения с сайта, когда Telegram недоступен

Гостевая форма на [mnebyvpn.site](https://mnebyvpn.site/#contact-support) создаёт запись в таблице `website_support_tickets`. Посетитель получает приватную HttpOnly cookie с 256-битным случайным токеном, может открыть сайт в том же браузере и прочитать ответ; ID заявки сам по себе не позволяет прочитать переписку.

В главном меню оператору отображается отдельная кнопка **«📥 Входящие заявки»**. Бот показывает необработанную заявку с контактом и описанием. Кнопки **«⬅️ Назад»**, **«➡️ Далее»** позволяют просматривать другие заявки; **«🔄 Обновить»** возвращает к актуальным обращениям. **«✍️ Ответить»** открывает поле ввода с привязкой к конкретной заявке. Отправленный ответ сохраняется в базе сайта, и посетитель видит его в своём браузере.

**Состояние 07.11.2026:** токен уже существующего бота подтверждён через Telegram `getMe` и приватно установлен для сайта. Продакшен-активация выполнила операторскую отправку с подтверждением Bot API (`real_operator_notification_delivered=true`). Полный маршрут реальной **клиентской** заявки сайт → оператор → ответ на сайте пока отдельно не подтверждён.

**При сбое Telegram:** сообщение остаётся в БД со статусом `PENDING`, браузер получает приватный cookie и ответ `{queued:true,webTicket:true}`. Оператор может открыть такую заявку вручную через «📥 Входящие заявки» и ответить на неё, не ожидая восстановления исходящей отправки. Статус `DELIVERED` выставляется только после подтверждения API; отсутствие подтверждения нельзя отображать как доставку.

## Приватная настройка

- Для идентификации оператора используется `SUPPORT_TELEGRAM_OPERATOR_ID`, найденный в прежней переписке владельца. Между ботом и сайтом используется **отдельный случайный `SUPPORT_BRIDGE_SECRET`** (HMAC-SHA256, 32 байта), сгенерированный на VPS при активации. Оба значения находятся только в приватных `/opt/mnebyvpn/bot/web.env` и `/opt/mnebyvpn/public/web.env`, а не в публичном Git.
- Для оператора использован `mnebyvpn-support-activate.yml` с зашифрованным ID. Для мгновенных уведомлений 07.11.2026 выполнен `mnebyvpn-support-enable-instant-notifications.yml` в инфраструктурном репозитории: он проверяет `getMe`, защищённо устанавливает **тот же** токен и делает проверку отправки оператору. Секреты и их значения не публикуются.
- При отсутствии или ошибке ID поддержка недоступна, а основной VPN-бот и биллинг продолжают работу.
- Секреты для подписи существующего Telegram webhook не меняются.
- Сайт и Telegram-бот используют **разные базы**: `mnebyvpn_public` и `mnebyvpn_stage` соответственно. Таблица обращений создаётся миграцией `db/migrations/0018_website_support_tickets.sql` именно в базе сайта; оператор получает заявки через подписанный локальный запрос `GET /api/support/operator-inbox` и сохраняет ответ через подписанный `POST /api/support/operator-reply`. Бот не читает и не изменяет таблицу в своей базе. В запросах действуют HMAC и проверка времени, секрет не передаётся клиенту.

## Защита и ограничения

- На каждом входящем Telegram update проверяется секрет webhook; только личный Telegram-аккаунт оператора может направлять ответы другим пользователям. Группы и сообщения от других отправителей отклоняются.
- Для формы сайта проверяются Origin, длина текста, контакт, honeypot и процессные ограничения частоты. Для реального антиспама требуется дополнительное ограничение на reverse proxy.
- Контакты и обращения хранятся 30 дней; нужна опубликованная политика обработки данных. Новая заявка в браузере заменяет cookie старой.
- Подтверждение работоспособности требует тестов клиент → оператор → клиент и сайт → inbox → сайт. Прохождение CI не равно реальной доставке сообщений.
- Сервис VPN и коммерческие сценарии остаются под собственными release gates.

Официальная документация Telegram: [Making requests when getting updates](https://core.telegram.org/bots/api#making-requests-when-getting-updates).
