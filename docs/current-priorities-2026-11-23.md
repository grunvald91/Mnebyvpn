# Текущие инженерные приоритеты MNEBYVPN / MNEBYDNS

Дата обновления: 2026-11-23. Это рабочая очередность по последним указаниям владельца, а не автоматическое разрешение на production-изменения. Исторический [ADR MVP от 06.11](mvp-scope.md) сохраняется как исходное решение; его устаревший порядок разработки **не определяет текущий следующий шаг**. Коммерческие и технические release gates из [реестра](release-gates.md) не отменяются.

**Главная конкретная незавершённая работа: завершить развёртывание Smart DNS и Telegram MTProxy/Telemt именно на финляндском FI217 (fi-test-01).** Не подменять её ремонтом уже работающего RU/DE DNS или расширением общего VPN-лимита. На FI уже подготовлен Telemt 3.5.17 (staged, systemd_installed=false, users_enabled=false): [проверка 23.11.2026](https://github.com/grunvald91/telegram-proxy-infra/actions/runs/45158573699). Для финского персонального DoT, срока/отзыва и живого Telegram-клиента внешний E2E ещё не подтверждён. Это требует завершения релиза FI, не только очередного read-only аудита.

**P0 FI Smart DNS:** проверить фактические CoreDNS/Nginx/TLS candidates на FI217, выпуск/проверку личного DoT hostname и сертификата, отдельные per-entitlement разрешения и немедленный отзыв; после теста закрытого доступа включить финский listener изолированно с резервной копией и откатом; затем Android Private DNS E2E с финской географией и заявленными маршрутами. Наличие действующего RU/DE Smart DNS не считается успехом для FI.

**P1 FI Telemt:** завершить подготовку безопасного systemd-сервиса, привязку персонального секрета к действующему RU188 entitlement, защищённый канал выдачи/отзыва, исключить публичный admin API и общие секреты; затем подтвердить внешним Telegram-клиентом подключение, сообщения, длинную передачу файлов, expiry/revoke и восстановление соединения на FI. Перенос/перезапуск немецкого Telemt не требуется.

**P2:** сохранить действующие RU/DE Smart DNS, DE Telemt и DE/FI VPN без регрессий. **P3:** только после завершения FI DNS/Telemt вернуться к общему лимиту одновременно активных VPN-подключений.

## Дополнительная работа: — завершить и стабилизировать персональный Smart DNS

Текущий персональный DoT и маршрутизация уже существуют. Не переписывать и не переустанавливать работающий стек по умолчанию; сначала read-only диагностика реального клиента и канала. Работы: задержка холодных/длительных запросов, утечки/неполные правила A/AAAA/HTTPS/SVCB, одинаковый актуальный источник персональных и общих правил, сброс upstream TLS и устойчивость при одновременных VPN+Private DNS. Проверка длительного видеопотока YouTube обязательна, а успех DNS/TLS-соединения не считать доказательством воспроизведения видео. Измерять p50/p95/p99 и долю отказов без утверждений об улучшении до внешнего E2E. Не обещать устранение DPI-блокировки TLS SNI посредством одной DNS-подмены.

Выходной критерий: подтверждённые Android Private DNS + персональный адрес, сертификат, отказ для чужого ключа, маршруты по согласованному каталогу и реальное продолжительное воспроизведение/работа заявленных сервисов; безопасное отключение просроченного персонального доступа без влияния на других абонентов.

## P1 — завершить Telegram MTProxy / Telemt

Сохранить существующие действующие Telemt/MTProto на германском узле. Проверять выдачу только личных секретов, срок, отзыв, переподключения при смене Wi-Fi/мобильной сети и загрузку больших файлов. Учитывать, что локальная Telemt admin/API находится на узле, а не в localhost российского контроллера. Не выставлять admin API в интернет. Финский Telemt в Nodekit — только кандидат со снятыми запретами **не является** действующей клиентской услугой, пока не выполнены подписанные entitlement-гранты, ограниченная доставка, внешние Telegram E2E и откат. Nginx SNI-шлюз для Smart DNS не является Telegram MTProxy.

Выходной критерий: подтверждённая настройка из бота без ручного копирования общих ключей, проверка отправки/получения сообщений и файлов в настоящем Telegram-клиенте, expiry/refund/revoke и восстановление после обрыва, с независимыми E2E на каждом опубликованном узле.

## P2 — поддержание VPN, без расширения функциональности

Не ломать уже используемые Германию и Финляндию, подписку и связанные сетевые службы. Исправления безопасности и регрессии допускаются. Реализация общего DE+FI лимита в `0147`–`0149` и подписанные решения **доказаны только на offline/изолированной БД**, не в трафике VLESS/AWG. Не включать `vpn_shared_connection_admission`, пока оба протокола не имеют реального до-приёма транспорта, локальной проверки TTL, испытаний обрыва RU188, одновременных подключений и внешнего клиентского E2E. Это отдельный поздний этап, а не причина откладывать Smart DNS и Telemt.

## Правило выбора следующего шага

После успешного ревью приоритет — P0 Smart DNS, затем P1 Telegram, затем P2 VPN. Слова «давай дальше» относятся к **текущему незавершённому P0/P1**, а не к самой длинной технической ветке. Не запускать автоматические сетевые изменения или коммерческую выдачу без независимого E2E, резервного плана и правил из [AGENTS.md](../AGENTS.md). По каждому этапу фиксировать реальный источник и границу подтверждённого результата, а не выдавать подготовленный код за работающий продукт.
