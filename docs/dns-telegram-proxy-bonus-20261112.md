# Бесплатный Telegram MTProxy как бонус к оплаченной Smart DNS

Дата: 2026-11-12. Статус: **код выдачи подготовлен, в production НЕ включён**. Нет двух подтверждённых iPhone-маршрутов с одним персональным Telemt-секретом и нет проверенного автоматического отзыва.

## Подтверждённые наблюдения, не домыслы

- Покупатель сообщил: на его iPhone **зарубежный** прокси подключился через **8443**, а на публичном **443** не подключается; задержка в Telegram более 500 мс. IP и профиль этой рабочей настройки не предоставлены, поэтому нельзя приравнивать её к российскому 188:8443.
- В legacy-снимке российского Nginx `188.120.254.223:8443` направляет TCP через WireGuard на `10.66.77.1:443`. Это технический вариант маршрута RU → DE, **но с iPhone пользователя он отдельно не проверен**.
- Зарубежный Telemt `rf-media` обслуживает `127.0.0.1:9470` с FakeTLS-доменом `media.bandbook.site`; этот порт не слушает публично. DE Nginx SNI `media.bandbook.site` → `127.0.0.1:9470`.
- На иностранном сервере `89.125.90.101:9446` уже есть прямой публичный Telemt **direct-ozon**, слушающий `0.0.0.0:9446` с FakeTLS-доменом `xapi.ozon.ru`. Тот же профиль доступен через внешний DE Nginx `443`, где активная схема содержит `xapi.ozon.ru -> 127.0.0.1:9446`. Следовательно, можно использовать **одного пользователя этого Telemt-профиля** одновременно для прямого и российского маршрута. Пароль другого Telemt-профиля `rf-media` к этому входу не подходит.
- Из ранее проведённых GitHub Actions TCP-проверок порт 9446 был доступен из точки тестирования; это не доказательство успешного входа Telegram с iPhone. Источник: https://github.com/grunvald91/telegram-proxy-infra/actions/runs/43229909069

## Два клиентских маршрута к ОДНОМУ Telemt-профилю direct-ozon

1. **Прямой иностранный:** `89.125.90.101:9446` → Telemt `direct-ozon`. Публичный порт 9446 был доступен при тестировании извне 12.11.2026; 443 не нужен.
2. **Через Россию:** `188.120.254.223:8443` → WireGuard `10.66.77.1:443` → DE Nginx по SNI `xapi.ozon.ru` → `127.0.0.1:9446` → **тот же** Telemt `direct-ozon`. Внутренний 443 остаётся необходим для Nginx, но у клиента Telegram порт 8443.

Оба входа способны использовать одного будущего персонального пользователя из `direct-ozon`, один 16-байтовый Telemt-секрет и один FakeTLS-домен `xapi.ozon.ru`. **Это проверенная конфигурационная совместимость, не завершённый iPhone E2E тест.** Существующий публичный :9446 и RU :8443 не требуют нового listener и не должны перенастраиваться. В личном кабинете ссылки будут иметь один секрет и два адреса.

`WEB_DNS_MT_PROXY_BONUS_ROUTES_JSON=[{"route":"direct","host":"89.125.90.101","port":9446},{"route":"ru","host":"188.120.254.223","port":8443}]`

Сборка нового пользователя должна обращаться к **локальному API Telemt direct-ozon** (из исторического снимка `127.0.0.1:9096`), не к `rf-media` на :9097. Сверить активную версию и поддержку API перед записью. Не брать общий секрет уже существующих пользователей direct-ozon.

## Доставка и управление доступом

В MNEBYVPN добавлен:
- стол `dns_mtproxy_bonus_credentials` с персональным `entitlement_id`, `telemt_username`, зашифрованным AES-GCM `secret_box`, `state`, `verified_at`, `disabled_at`;
- серверный endpoint `GET /api/telegram-proxy-bonus?entitlementId=UUID`, использующий подтверждённую авторизованную сессию, только `ACTIVE` Smart DNS, не истёкшую подписку и `PAID` заказ (`smart_dns` или `bundle`); бесплатная проба и отменённая/возвращённая оплата не проходят;
- две подписанные по параметрам Telegram-ссылки `https://t.me/proxy?server=...&port=...&secret=ee...` в кабинете; клиенту не требуется перепечатывать ключ;
- для каждого пользователя секрет хранится исключительно в зашифрованном виде, ключ шифрования задаётся только окружением сервера;
- все функции отключены по умолчанию (fail-closed).

**Чего ещё нет:** worker для создания пользователя через локальный Telemt API и автоматического `disable` при окончании/возврате, реальный iPhone E2E двух маршрутов к Telemt direct-ozon. Серверная выдача не умеет сама создавать пользователя — она читает уже подтверждённую серверную запись.

По официальному API Telemt есть `POST /v1/users` и `POST /v1/users/{username}/disable`, но перед использованием на установленной версии нужно отдельно подтвердить поддержку и обновление действующего процесса:
https://github.com/telemt/telemt/blob/main/docs/Architecture/API/API.md

## Активация после испытаний

Только после подтверждения:
- два реально работающих iPhone-соединения к профилю direct-ozon, включая обмен медиа; сравнение задержки на той же Wi-Fi и мобильной сети;
- создание/повторная выдача **одного** персонального Telemt-пользователя для конкретной оплаченной DNS-подписки;
- отзыв сразу после refund/expiry и отсутствие возможности подключения по старому секрету (включая существующие сессии);
- проверенная миграция на основной базе, read-only website role и отсутствие ключей в логах/репозитории;

разрешается на сайте выставить одновременно все флаги (сейчас **не выставлены**):
- `WEB_DNS_MT_PROXY_BONUS_ENABLED=yes`
- `WEB_DNS_MT_PROXY_BONUS_E2E_VERIFIED=yes`
- `WEB_DNS_MT_PROXY_BONUS_REVOKER_VERIFIED=yes`
- `WEB_DNS_MT_PROXY_BONUS_KEY=<64-символьный HEX из надёжного генератора, только server env>`
- `WEB_DNS_MT_PROXY_BONUS_ROUTES_JSON=[{"route":"direct","host":"89.125.90.101","port":9446},{"route":"ru","host":"188.120.254.223","port":8443}]`

Нельзя устанавливать флаги по результатам одного TCP-теста. Нельзя выпускать два URL с одним секретом, если они доставляют запросы к разным Telemt-профилям. Персональный секрет действует и после закрытия страницы: требуется **реальное серверное отключение**, а не только скрытие ссылки.

До активации Smart DNS сайт продолжает честно показывать услугу как разрабатываемую; бонус не заявляется как уже действующая услуга. Финальный коммерческий gate для DNS и платёжного провайдера остаётся отдельным.

Примечание: публичный порт 443 можно исключить из клиентских ссылок MTProxy, **но нельзя просто закрывать его на VPS**: действующие HTTPS-сервисы и внутренние Nginx TCP-маршруты используют этот порт.
