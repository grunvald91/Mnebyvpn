# Инфраструктура — публичный контракт ресурсов и безопасного развёртывания

Дата проверки документа: 2026-11-06. **Настоящие адреса, назначения VPS, текущие порты, процессы, firewall и audit-run IDs не публикуются.** Актуальная сеть не измерена в рамках этого изменения. Старый публичный snapshot более не считается актуальным после заявленного владельцем изменения ресурсов. Удаление строк из HEAD **не устраняет старую git-историю и внешние audit-логи**.

## Требования upstream и проверка вместимости

Официально для Remnawave Panel: **минимум 2 CPU, 2 GB RAM, 20 GB storage**, рекомендовано **4 CPU, 4 GB RAM, 20 GB storage**. Для Remnawave Node: **минимум 1 CPU, 1 GB RAM**, плюс нагрузка от Xray. Источник: https://docs.rw/install/requirements/ . Минимум для панели **не является гарантией**, что панель, PostgreSQL, API, бот и старые службы совместно поместятся на одном VPS.

Владелец сообщил о расширении одного VPS до 2 vCPU / 4 GB RAM. **Не могу подтвердить это live-аудитом в рамках текущего репозитория.** До установки сделать свежий приватный снимок `nproc`, `free -h`, `df -h`, uptime/CPU steal, CPU/RAM/swap trends, backup storage, conntrack и сеть на каждом узле; проверить ресайз и фактическую свободную ёмкость. Не публиковать результаты с идентификаторами сети.

## Целевое размещение (условное)

| Компонент | Роль, без публичного назначения VPS | Условие |
|---|---|---|
| Panel + база + MNEBYVPN TypeScript API/bot/worker | Control plane | Достаточно CPU/RAM/storage поверх уже работающих служб; админка недоступна из интернета без закрытого управления |
| Remnawave Node + Xray | Изолированный data-plane pilot | Раздельные тестовые listeners; отсутствуют конфликты; подтверждён отзыв доступа и expiry в реальной сети |
| Внешние probes | Независимая от VPS точка контроля | Минимальные анонимные метрики/алерты без секретов |
| MNEBYDNS DoH/DoT/SNI | **DEFERRED** | Не включать вместе с MVP без независимой auth, PTR/RR, capacity, IPv4/IPv6 и traffic quota PoC |
| AI autoscaling / special nodes | **DEFERRED** | Hard spending budget и отдельное разрешение владельца |

## Приватный preflight перед изменениями

1. На каждом VPS проверить неожиданные **публичные** TCP/UDP listeners: локальное `ss`, firewall + реальный внешний тест без credentials. При найденном open proxy — ограничить доступ безопасно и с проверкой действующих зависимостей; не выключать неизвестный сервис вслепую.
2. Согласовать одни-единственные порты и SNI маршруты в **приватной** сетевой карте. Remnawave Node с host networking может конфликтовать с процессом хоста. HTTPS/DoH/SNI по одному IP:port без явного mux не сосуществуют.
3. Создать offsite backup, испытать восстановление, указать rollback/подтверждение отсутствия регрессии старых сервисов.
4. Внедрять лишь staged VPN. Без отдельных полномочий не менять боевые proxy, firewall, DNS, сертификаты, routing.
5. Получить владельцу приватный отчёт с данными **после** resize и принять capacity-решение; без измерений статус [P0-NET](release-gates.md) остаётся BLOCKED.

До измерений нельзя утверждать ни «сервера точно недостаточно», ни «сервер уже подходит».
