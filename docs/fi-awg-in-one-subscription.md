# FI217 в общей VPN-подписке RU188 (INCY)

## Один доступ — все разрешённые серверы MNEBYVPN

Источник прав, оплаты, срока и отзыва — существующие `entitlements`,
`provisioning_state` и `vpn_subscription_links` PostgreSQL на RU188.
Клиент продолжает пользоваться **той же HTTPS-ссылкой**
`https://cdn.servgo.ru:8443/sub/<token>`. Дополнительная регистрация
или оплата «Финляндии» не предусмотрена.

В существующей подписке по информации владельца уже есть один AWG
и две конфигурации VLESS (последние пока неработоспособны; удаление
будет отдельным этапом). **Приоритет — AWG, VLESS не считаем опорным
туннелем и не изменяем в этом выпуске.** После обновления подписки
в **INCY Android/iOS** дополнительной строкой должен появиться
`amneziawg://<base64url-conf>#мне VPN Финляндия` (в URL подпись кодируется).
Тип туннеля и параметры протокола остаются в конфигурации, но не в названии.

Официальный формат INCY:
https://docs.incy.cc/subscription-format/ (построчный смешанный формат).
На Desktop INCY AmneziaWG в таком виде не работает; для Karing
существующие VLESS-ссылки сохраняются.

## Как выдаётся доступ без отдельной кнопки

1. Асинхронный контроллер RU188 раз в минуту выбирает небольшую порцию
   активных VPN-подписок с подтверждённой основной выдачей доступа.
2. Для каждой подписки RU188 получает **стабильный отдельный** X25519
   публичный ключ из защищённого секрета RU188 и существующего
   `entitlement_id`. Приватный ключ не отправляется FI217.
3. Публичный ключ ставится в существующую
   `vpn_awg_device_requests`; уже существующая привязка не
   перезаписывается и не ротируется автоматически.
4. Уже работающий root-worker подписывает разрешение Ed25519, отправляет
   через outbox на FI217 и ждёт подписанное подтверждение FI217.
   Локальный watchdog на FI217 проверяет время действия автономно.
5. При `GET /sub/<token>` RU188 проверяет **то же право доступа и
   срок** в существующей БД, а также актуальное состояние FI217,
   доказательство E2E, точную привязку к ключу клиента и signed ACK.
   Только после этого дополняет исходную подписку строкой AmneziaWG.
   Если FI временно недоступна, исходный список серверов
   возвращается без изменения, включая существующий AWG. Исправность
   VLESS не предполагается. Никаких RPC к RU188 при VPN-handshake нет.
6. Истечение срока или отмена оплаты запускают существующий механизм
   асинхронного отзыва со всех серверов.

## Настройки RU188

- `AWG_INCY_SUBSCRIPTION_SEED`: криптографически случайный секрет
  32 байта в нижнем регистре hex (64 символа), **один и тот же**
  для root-контроллера RU188 и процесса подписок RU188.
  Не сохранять в Git, GitHub Actions, пользовательский браузер,
  клиентский конфиг или логи. Ротация требует контролируемого
  перевыпуска всех FI peer, поэтому запрещена автоматически.
- `WEB_FI_AWG_IN_SUBSCRIPTION_ENABLED=yes`: включает строку FI
  в **существующей** подписке INCY, но только при активном
  `WEB_FI_AWG_MATERIAL_ENABLED=yes` и подтверждённых FI-ключах.
- Развёртывание новой версии worker на RU188 обязательно. При
  отсутствии seed авто-регистрация не происходит.

Публикация кода сама по себе **не доказывает**, что seed установлен
на RU188, новая версия worker внедрена и хотя бы одна реальная
подписка получила подтверждённый FI peer. Перед утверждением релиза
нужно выполнить live Actions-проверку канонической БД и внешней
подписки с уже действующим токеном без раскрытия самого токена.
