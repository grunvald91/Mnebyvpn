# Этап 7: реферальные HTMLBubbles для MNEBYVPN

## Сценарий

1. Покупатель или рекомендатель вызывает `/share` в личном чате.
2. Бот берёт **действующие** тарифы из PostgreSQL. Для каждого тарифа создаётся стабильный случайный реферальный токен, связанный с Telegram-аккаунтом рекомендателя и `plan_id`, без публичного раскрытия его Telegram ID.
3. Бот отправляет **статический `sendWidget` с `public_data`**: VPN, MNEBYDNS, название и цена в ⭐/₽ из каталога. Пересылка переносит только публичный каталог и ссылки. `chat_data` отсутствует.
4. Получатель нажимает «Выбрать». Сам HTML не обращается к сети: `TelegramWidget.openTelegramLink` открывает `https://t.me/<configured_bot>?start=r<opaque_token>`. Если Telegram старый, caption сохраняет переход для первого предложения.
5. Бот по `/start r<token>` проверяет действующий тариф, создаёт заказ с единым `order_referrals`, сформированным внутри транзакции. Self-referral блокируется. Цена берётся из `order_terms`.
6. Открывается **Stars invoice** (не списание без подтверждения). Рубли в карточке — информационная цена для отдельно реализуемой авторизованной оплаты через **Продамус** на внешнем сайте.

## Реализация

- `db/migrations/0006_referral_invites.sql` — таблицы кодов приглашения и атомарной атрибуции заказа. Комиссии и выплаты отсутствуют.
- `packages/billing/src/store.ts` — `referralOffers`, `referralPlan`, optional referralToken в заказе, self-referral и запрет подмены источника повторным запросом.
- `packages/telegram-ui/src/referral-widget.ts` — независимый от личной панели пересылаемый Widget, public_data до 1024 bytes и HTML до 32 KB / zlib до 3800 bytes.
- `packages/billing/src/handlers.ts` — `/share`, `/start r<token>`; Stars invoice по snapshot; личные `/my`, `/status` не пересылают сведения.
- `apps/service/src/payments-server.ts` — username берётся из `TELEGRAM_BOT_USERNAME` **только из конфигурации**; без имени /share отказывает.
- `tests/referral-widget.test.ts` и `tests/integration/referral-flow.test.ts` — проверка публичных ссылок, цен, отсутствия приватного контента, атрибуции и гонок.

## Проверки, ограничения и запуск

- Цены не заданы в коде. Они появляются только при `billing_plans.enabled=true`.
- Индекс карточек не является платёжным идентификатором. Личная карточка привязывает кнопку к digest серверного тарифного предложения, изменение цены или условий инвалидирует старую кнопку.
- Один публичный Bubble показывает до 3 тарифов в текущем MVP. Для добавления большого каталога нужны дополнительные сообщения или пагинация.
- Оплата через Продамус **не заменена** Stars: внешний web checkout запланирован, но в реферальном сценарии ещё не подключён.
- Нет live Telegram/Prodamus/Stars E2E, VPS не затронуты, PR остаётся Draft.
