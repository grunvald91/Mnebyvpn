# Ревью MNEBYVPN PR №1: Telegram Widgets и реферальные покупки

Дата: 2026-11-06. Проверены handlers.ts, store.ts, widget-104.ts, SQL 0001–0006, тесты и Telegram widget-sandbox/docs/tgw-format.md (layer 233, Bot API 10.4).

## Подтверждённые замечания

| Приоритет | Проблема | Результат |
|---|---|---|
| P1 | Покупка `buy:0` выбирала тариф по индексу из заново загруженного списка: при изменении сортировки/прайса могла уйти на иной план | Исправлено: 16-символьный ключ как digest конкретных условий (ID, название, Stars, продукт, длительность, DNS квота); handler сопоставляет по текущему каталогу, при смене условий требует обновления |
| P1 | Invoice использовал живой тариф вместо зафиксированных условий `order_terms`: смена цены после заказа приводила к ошибке или рассинхронизации | Исправлено: `pricedPlanForOrder(order)`, для Stars invoice только snapshot из PostgreSQL |
| P1 | Личная карточка не должна одновременно быть пересылаемым реферальным предложением: иначе можно смешать приватный `chat_data` и публичный `public_data` | Разделены два независимых widget: личный статический `sendWidget(chat_data)` и публичный реферальный `sendWidget(public_data)`; в public нет токенов доступа и Telegram ID пригласившего |
| P1 | Атрибуция приглашения без идемпотентности позволила бы менять источник после повторов заказа | SQL `order_referrals` (один к одному с order), FK на `referral_invites`, проверка совпадения inviteToken при replay, self-referral blocked |
| P2 | Пересланная карточка может показывать вчерашнюю цену | Виджет явно пишет, что цена предварительная; перед Stars checkout бот получает актуальный план и сохраняет immutable цену заказа |
| P2 | До первого платежа реферер может создавать любое количество pending orders через повторные `/start` | На запуске потребуются TTL уборка ожидающих заказов, rate limiting пользователя/чата и мониторинг; пока не реализовано |
| P2 | Widget-query с DB/API запросами может превышать серверный таймаут 15 с | Нужны deadline, наблюдаемая latency, backpressure и полезное сообщение при задержке; CI с fake API не доказывает SLA |
| P2 | Реальные Bot API 10.4 widgets и Stars/Prodamus не прошли end-to-end | Gate остаётся закрытым до live тестов, санкционированного запуска, проверки реальных провайдеров и hard quota ingress |

### Продуктовые решения
- Поддерживаются **Продамус** и **Telegram Stars**. В реферальной карточке могут показываться обе цены, только из реального `billing_plans`; RUB как копейки / 100. Никаких валютных пересчётов.
- Через `t.me/<bot>?start=r<token>` сразу выбирается конкретный тариф и открывается счет **Stars** в боте (оплата требует явного согласия покупателя). Для оплаты рублями через Продамус нужен отдельно аутентифицированный внешний checkout; он ещё не подключён, его нельзя имитировать.
- Реферальный ID — для атрибуции источника. Бонусы, выплаты, проценты, возвраты бонусов и мошенничество не определены владельцем и не реализованы.
- Максимум три оффера в первом пересылаемом Bubble, ограничение 1024 байта public_data. Каталог с дополнительными тарифами остаётся в ботe; масштабируемую пагинацию следует реализовать отдельно.
- Сквозное тестирование реального `sendWidget`, старых клиентов и пересылок остаётся задачей перед продом.
