# MNEBYVPN — очередность работ (не реестр фактов готовности)

Дата: 2026-11-06. **Единственный список статусов PASS/BLOCKED: [release-gates](release-gates.md).** Здесь последовательность; никаких [x], которые можно перепутать с рабочим продуктом. Принятый объём: [mvp-scope](mvp-scope.md).

## Этап 0. Безопасность текущей инфраструктуры (P0)

1. Свежий **приватный** ресурсный аудит **после** последнего resize; конфигурация и показатели загрузки, filesystem, маршрут/адрес, bandwidth и backup. Ранее опубликованные замеры устарели.
2. Вне публичного репозитория проверить нештатные сетевые listeners: firewall, ACL, обязательная авторизация, попытка доступа без credentials. Без факта не объявлять open proxy. При выявлении риска подготовить и выполнить минимальное исправление с rollback по отдельному разрешению.
3. Независимый backup и restore-test, пинованные версии Docker/Remnawave/Node/Xray; контроль отсутствия регрессии у существующих сервисов.
4. Измерить свободные ресурсы под панель согласно https://docs.rw/install/requirements/ (минимум 2 CPU, 2 GB RAM, 20 GB storage). Никаких автоматических покупок новых VPS.

## Этап 1. VPN data plane (P0)

1. Изолированный Remnawave + Node пилот без изменения живых listener/прокси.
2. Реальная выдача 24h trial только после node-observed activation и hard expiry, импорт в два клиента, server-side revoke и квота там, где она подтверждена.
3. **Первым сетевым экспериментом:** Panel ↔ Node network partition за несколько минут до expiry; тест новых и существующих TCP/UDP соединений, reboot, clock skew, восстановление и refund. Сохранить **обезличенные** доказательства.
4. Фактический порядок работы revision/fencing на реальном adapter, pending outbox/reconcile и восстановление. Offline симулятор существует, но не считается сетевым тестом.

## Этап 2. Продажи и клиентский путь (P0)

1. Утвердить цены для 15/30/60/90 дней, тестовые квоты, правила общего VPN-использования и trial, расчёт себестоимости: [commercial-readiness](commercial-readiness.md).
2. Реальные merchant test vectors + сверка provider capture/refund; Stars внутри Telegram, отдельно независимый Prodamus website checkout при допустимой модели продажи.
3. Независимый HTTPS кабинет с login/session/CSRF и привязкой account id на сервере; оставшиеся дни, байты, продажа/продление, ссылки/действия, поддержка и ошибки.
4. Юридическая проверка РФ/целевого рынка, договор услуг, ПДн, реклама, возвраты и чек до приёма денег.
5. E2E на контрольных клиентах, отсутствие регрессий, восстановление после отказа панели и платёжного канала.

## Этап 3. Исследования (DEFERRED)

- DNS-only resolver (не рекламировать как VPN), test-only SNI ingress с доказанной независимой auth/общим учётом, DNS RR/IPv6/IPv4-only/ECH/QUIC; без этого не продавать GB по одному DNS-имени.
- VPN/Private DNS coexistence и Android Always-on/kill switch после реального клиента.
- AI-ops, autoscaling, дополнительные специальные узлы — только при измеренной потребности и hard budget; не часть первой поставки.

Обновления по проверенным фактам вносятся **только** в [release-gates](release-gates.md) с версией, сценарием и датой. Документирование/непроверенные эмуляции отмечаются отдельно.
