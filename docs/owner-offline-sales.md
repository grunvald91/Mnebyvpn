# Личные продажи MNEBYVPN — 30 дней «3 в 1»

**Назначение.** Выдать собственноручно проданный доступ без сайта, платежной
системы и Telegram `/start` у покупателя. Все операции делает владелец
в личном чате с `@MnebyVPN_bot`. Покупателю ничего автоматически не отправляется.

## Учёт

- `manual_sales` (миграция 0141): реестр с `operator_telegram_id`,
  клиентским ярлыком `@username`, фактически заявленной суммой,
  необязательным номером фискального чека и ключом операции.
- `orders.provider='manual_sale'`, `orders.state='PAID'` —
  **подтверждение владельцем полученной оплаты**, НЕ callback PSP.
  `verified_payment_events` и `provider_captures` не заполняются
  и не имитируются. История этих каналов остаётся неизменной.
- Отдельный анонимный `accounts.id` и собственная пара `vpn` /
  `smart_dns` `entitlements`, `entitlement_credits`,
  `reconcile_outbox` для каждой продажи. Лимит DNS 1 млн запросов/30 дней;
  VPN — до трёх устройств. Срок начинается при фиксации продажи,
  поэтому оформляйте запись непосредственно перед передачей.
- `@username` — только подпись в реестре; она НЕ доказывает личность,
  не присваивает Telegram ID и не привязывает будущий аккаунт.
  Для последующей привязки требуется отдельная проверка владения
  через аутентифицированного Telegram-бота/сайт.
- Повторная доставка того же Telegram update идемпотентна;
  новую активную продажу тому же ярлыку без отдельного сценария продления
  создать нельзя.

## Владелец: интерфейс

При `MNEBYVPN_OFFLINE_SALES_ENABLED=yes`, настроенном
`DNS_ADMIN_TELEGRAM_ID` (либо `SUPPORT_TELEGRAM_OPERATOR_ID`)
и закрытом Telegram webhook на главном экране владельца появляется
«💼 Личные продажи».

«➕ Продать 3 в 1» → ответ `@username сумма_руб [номер_чека]`,
например `@customer 399`. Сумма — фактически полученная, без
автоматического предположения о цене. Чек оформляется вне MNEBYVPN,
например в приложении «Мой налог» при применимости. Отсутствие
`receipt_reference` отображается как ещё не отмеченный чек.
Никакой API налоговой службы в текущий выпуск не включён.

«📋 Покупатели и ссылки» → покупатель → «🔑 Получить ссылки».
Только в чате оператора выдаются **после подтверждения сетевых адаптеров**:

- VPN: стабильная HTTPS-подписка `/sub/<token>`, привязанная к
  подтверждённому узлом VPN entitlement. Повторное открытие той же покупки
  возвращает тот же URL, не добавляя новые действующие токены. Токен
  детерминированно выводится через domain-separated HMAC-SHA256 из
  приватного `MNEBYDNS_OWNER_LINK_KEY` и владельца/заказа/подписки;
  база хранит только SHA-256, а при отзыве ссылки повторная выдача
  запрещена. Для неизменности URL сохраняйте ключ при резервном копировании.
- Smart DNS: отдельный персональный DoT hostname, созданный атомарно
  вместе с зашифрованным материалом; повторное открытие показывает
  тот же hostname без перевыпуска. Требуется
  отдельный закрытый переключатель
  `MNEBYVPN_OFFLINE_DNS_ISSUE_ENABLED=yes` и
  `MNEBYDNS_OWNER_LINK_KEY` (существующий 32-byte hex ключ).
  Он **не активирует публичные тарифы/пробные DNS** через
  `MNEBYDNS_PERSONAL_DOT_ENABLED`. До выдачи требуются
  `PAID` личный заказ, `ACTIVE` Smart DNS, подтверждение текущей
  версии `provisioning_state` адаптером `smart_dns` и проверенный
  рабочий шлюз DoT. Повторный просмотр не меняет адрес.
  При отзыве запись остаётся в реестре, но адрес больше не показывается.
- Telegram Proxy: ссылки только после действительного Telemt ACTIVE;
  используется существующий приватный `WEB_DNS_MT_PROXY_BONUS_KEY`
  и две проверенные маршрутизации `WEB_DNS_MT_PROXY_BONUS_ROUTES_JSON`.
  Обязательно штатное `bonusReleaseReady()`.
  Если у бота нет этих защищённых env, он сообщает, что ссылка недоступна,
  но не выдумывает её. Не выводить секреты в GitHub Actions logs.

## Безопасный выпуск

1. CI мигрирует одноразовую PostgreSQL и запускает интеграционный тест.
2. На 188 проверить, что источник подписок — существующий контроллер,
   создать свежий резервный `pg_dump -Fc`, применить 0141 к канонической БД.
   Существующий staging installer умеет делать предварительный dump
   и применять ещё не применённые миграции.
3. Только после успешных canary и проверки воркеров поставить флаг
   `MNEBYVPN_OFFLINE_SALES_ENABLED=yes` в приватный bot env
   и перезапустить только Telegram container с rollback.
4. Проверить один изолированный фиктивный заказ в тестовой БД:
   две entitlements, ноль PSP событий, один outbox на адаптер,
   no-leak без права владельца, двойная доставка idempotent.
   **Не создавать фиктивно оплаченные покупки в production.**
5. Затем владелец вводит реальные продажи. Доступ считается выданным
   только после подтверждения VPN, DNS и Telemt, не после INSERT.
   Полноценный 3-в-1 E2E на реальном клиенте обязателен.

Нельзя считать успешную миграцию доказательством работающего VPN,
DNS или Telegram Proxy. Не включать публичный API для ручных продаж;
не публиковать ссылки в CI, логах или групповых чатах.
