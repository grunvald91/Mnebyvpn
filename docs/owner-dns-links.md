Персональные ссылки Smart DNS владельца
====================================

В боте: «Управление Smart DNS» → «Персональные ссылки». Доступ имеет только
числовой Telegram ID из DNS_ADMIN_TELEGRAM_ID (либо существующего
SUPPORT_TELEGRAM_OPERATOR_ID, если первый параметр отсутствует). Подписанный
webhook, личный чат и совпадение chat.id/from.id обязательны. Имена пользователей,
группы и пересланные callback не дают прав.

Постоянная ссылка выдаётся один раз и повторно показывается без смены адреса.
Временные ссылки можно создавать на 1 час, 24 часа, 7 или 30 дней, либо задать
срок от часа до 3650 дней. Срок действующей временной ссылки можно изменить;
новый срок начинается от обработки команды. Повторная доставка той же команды
не продлевает срок повторно. Временную ссылку можно отозвать. Ссылки передаваемые:
человек, которому передан адрес, имеет доступ до его истечения или отзыва.

Это отдельный доступ владельца без платёжного заказа и без расходования
пользовательских пакетов. Ограничение частоты и числа соединений сохраняется.
Истечение/отзыв проверяются на каждом запросе, в том числе в открытом TLS,
до и после получения upstream-ответа. При отказе БД доступ закрывается.
Обычные оплаченные персональные DNS-подписки продолжают использовать квоты.

Режимы видеодоменов (миграция 0130)
-----------------------------------

Персональные ссылки владельца имеют **две явные политики** с разными
DoT-адресами и независимой повторной проверкой авторизации.

* «🌐 Smart DNS без VPN»: новая постоянная ссылка или временная ссылка с
  video_route=smart_dns. A-запросы к googlevideo.com и *.googlevideo.com
  проходят через проверенный mapped DNS upstream и должны давать адрес DE89
  при соответствующей рабочей политике. Обычные домены подчиняются classifier.
* «🛡 DNS для VPN (старая ссылка)»: ранее выданный адрес **не меняется**,
  video_route=vpn_origin. A-запросы к googlevideo.com направляются через
  direct upstream, чтобы VPN сохранил реальные IPv4 CDN.

AAAA, HTTPS, SVCB для видеодоменов продолжают получать NODATA в обоих
режимах, как в прежней политике IPv4-only. Остальные тарифы и персональные
пользовательские ссылки в этой миграции не меняются.

Флаг выпуска: MNEBYDNS_OWNER_SMART_DNS_LINKS_ENABLED=yes только в приватном
окружении Telegram-бота, и только после того как персональный DoT gateway
на RU188 обновлён, имеет миграцию 0130 и прошёл canary. По умолчанию флаг
не установлен, новые ссылки не показываются и даже прямой Telegram callback
на их создание отвергается **без обращения к БД**. Старые действия доступны.
Владелец не должен получать «готовую» новую ссылку раньше работоспособного
маршрута; без последующей Android проверки реального media сегмента успех не заявлять.

Режим привязан к записи ссылки, **не определяется по IP клиента или факту
включения VPN** (Nginx может скрывать реальный адрес). Включение VPN при
использовании Smart DNS-ссылки само по себе не меняет политику, может добавить
лишний переход и требует отдельного E2E испытания. Автоматическое переключение
по одному и тому же DoT hostname **не реализовано**. Если нужны две разные
DNS-политики, пользователь явно выбирает соответствующий адрес в настройках.
Нельзя обещать автоматическое переключение при включении VPN.

Порядок релиза: применить миграцию 0130 (с обратимо проверяемым бэкапом БД),
обновить единый сервис bot + personal DoT gateway, затем выполнить контракт
db/tests/0130_owner_dns_video_routes_contract.sql, тесты Node и приватный
DoT-запрос A/AAAA/HTTPS/SVCB через новую ссылку; проверить действительность
старой VPN-ссылки и отзыв временной новой ссылки. **Не менять** CoreDNS,
GooglePilot, Nginx, WireGuard, nfqws или оплаченные DNS подписки. До успешной
пробы реальной загрузки сегмента googlevideo.com через Android Smart DNS нельзя
считать воспроизведение YouTube восстановленным.

Хранение: SHA-256 случайного label и AES-256-GCM ciphertext. Секрет шифрования
MNEBYDNS_OWNER_LINK_KEY — отдельные 32 случайных байта в hex, постоянный private
runtime config бота; его нужно резервировать вместе с БД. В AAD включены UUID
записи и Telegram ID. Plaintext hostname не записывать в репозиторий и логи.

Выпуск: миграция 0126, явные права bot role на owner_dns_links и owner_dns_link_edits,
gateway role — только EXECUTE owner_dns_link_status(text). Сначала проверить
изолированный gateway, затем включить MNEBYDNS_OWNER_LINKS_ENABLED=yes у private
DoT. Общий публичный DNS отключать отдельным сетевым изменением после проверки
персонального доступа и переноса клиентов. Внутренний mapped DNS upstream должен
остаться доступен gateway. Старый image и runtime configs сохранять для отката.

Бессрочность означает отсутствие даты окончания, при сохранении сервиса,
домена и ключа. Персональный DNS не устраняет блокировку TLS по SNI и не заменяет VPN.
