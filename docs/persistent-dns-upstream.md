Постоянные TLS-соединения с вышестоящим DNS
========================================

У private DoT gateway появился ограниченный пул upstream-соединений, который
включается параметром `MNEBYDNS_DOT_POOL_ENABLED=yes`. Пул создаётся отдельно
для mapped и direct DNS. Повторное использование соединений убирает повторные
TCP/TLS handshake из каждого запроса, как рекомендует
[RFC 7858 §3.4](https://www.rfc-editor.org/rfc/rfc7858.html#section-3.4).

По умолчанию: до четырёх соединений на upstream, один запрос в полёте на сокет,
очередь до 32 запросов, idle timeout 30 секунд. Общее время запроса включает
ожидание в очереди, подключение и получение ответа. Переполнение очереди,
тайм-аут и отмена возвращают ошибку вызывающему коду. Автоматических повторов нет.

TLS проверяет имя сервера, системную цепочку доверия и срок сертификата.
Соединение обновляется не позднее пяти минут или 4096 сообщений. Для каждого
запроса на сокете используется новый DNS ID; ответ проверяется по ID, вопросу и
размеру, после чего исходный клиентский ID восстанавливается. Неожиданный,
дублированный или некорректный ответ закрывает соединение. Отменённый запрос
также закрывает его сокет, чтобы поздний ответ не попал следующему клиенту.

Пул не кеширует ответы, не хранит персональные hostname и не принимает решений
о доступе. Проверки идентичности, срока, отзыва, лимитов и settlement остаются
на прежнем пути обработки каждого запроса. Изменение включается после canary
с теми же проверенными сертификатами и сохранённым предыдущим gateway.
