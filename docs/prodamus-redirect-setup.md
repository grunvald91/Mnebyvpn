# MNEBYVPN: настройка возврата покупателя из Prodamus

Проверено по официальным материалам:
- https://help.prodamus.ru/payform/nastroika-platezhnoi-stranicy/kak-nastroit-pereadresaciyu-posle-uspeshnoi-ili-neudavsheisya-oplaty
- https://help.prodamus.ru/payform/integracii/rest-api/instrukcii-dlya-samostoyatelnaya-integracii-servisov

## Что необходимо настроить у продавца

1. Войти на **свою** платёжную страницу Prodamus (адрес формы **не** подставлять из примеров).
2. Открыть **Настройки → Настройка адресов**:
   - **Success URL**: `https://mnebyvpn.site/payment/success`
   - **Fail URL**: `https://mnebyvpn.site/payment/return`
   - Нажать **Сохранить**.
3. Открыть **Настройки → Настройка уведомлений** и проверить URL для HTTP-уведомлений:
   - `https://mnebyvpn.site/webhooks/prodamus`
   - Секретный ключ подписи на сервере должен соответствовать ключу платёжной страницы. Никогда не копировать ключ в frontend, GitHub Issue/PR или сообщения поддержки.
4. Нужные методы оплаты и поля контактов настроить отдельно в собственной форме.
5. Не путать: `Success URL` и `Fail URL` адресуют **покупателя**, а `/webhooks/prodamus` обслуживает **серверное подтверждение оплаты**.
6. Эти настройки вводятся владельцем через Prodamus. Изменение в репозитории не может само сохранить их в кабинете мерчанта.

## Что должно быть настроено на сервере MNEBYVPN

| Env | Значение/правило |
| --- | --- |
| `WEB_BASE_URL` | `https://mnebyvpn.site` |
| `PRODAMUS_SUCCESS_URL` | `https://mnebyvpn.site/payment/success` |
| `PRODAMUS_RETURN_URL` | `https://mnebyvpn.site/payment/return` |
| `PRODAMUS_NOTIFICATION_URL` | `https://mnebyvpn.site/webhooks/prodamus` |
| `PRODAMUS_FORM_URL` | Реальный HTTPS адрес формы продавца на `*.payform.ru` |
| `PRODAMUS_SIGN_SECRET` | Непубличный действующий ключ из Prodamus |
| `PRODAMUS_SYS` | Только если Prodamus согласовал код интеграции; иначе `urlNotification` указывать непосредственно в кабинете |

Сайт обслуживает `/payment/success` и `/payment/return` как состояния единого интерфейса. Для каждой новой оплаты сервер добавляет `order` и `payment=returned` или `payment=return` в подписанные URL, чтобы после возврата показать **свой** заказ. API-установка `urlSuccess` имеет приоритет перед общими настройками в Prodamus.

## Правильный алгоритм выдачи доступа

1. Сервер создает заказ в БД и подписанную ссылку Payform; покупатель оплачивает на стороне Prodamus.
2. Переход покупателя по `urlSuccess` — **не подтверждение оплаты**.
3. Prodamus направляет уведомление на `POST /webhooks/prodamus`. Сервер проверяет подпись, сумму, заказ и идемпотентность.
4. После признания заказа оплаченным VPN-узел активирует доступ. Датой начала действия оплаченного срока управляет серверная активация.
5. Страница возврата запрашивает авторизованный `/api/me` и показывает «Проверяем», «Оплата подтверждена, подготавливаем подключение» либо запускает мастер настройки **только при ACTIVE**.
6. При возврате **без оплаты** `urlReturn` показывает отсутствие подтверждения, но не создаёт доступ и не говорит, что деньги гарантированно не списались.

## Приёмка до включения в production

- [ ] `WEB_BASE_URL` и домен действительно совпадают; обе страницы доступны по HTTPS.
- [ ] `PRODAMUS_SUCCESS_URL` / `PRODAMUS_RETURN_URL` на работающем сервере актуальны.
- [ ] Проверить `do=link`, подстановку подтверждённого `customer_email` и фактический подписанный `urlSuccess` в создаваемом заказе.
- [ ] Проверить отменённую оплату: нет ложного `PAID`, интерфейс предлагает проверить статус.
- [ ] Проверить подтверждённую оплату с реальным webhook и реальной активацией узлом. Если webhook опережает клиента — открывается установка, если отстаёт — показывается ожидание.
- [ ] Проверить ошибочную подпись, дубликат webhook, возврат платежа, истечение сессии и повторное открытие страницы.
- [ ] На реальном смартфоне проверить переход в INCY/Karing, fallback копирования и кнопки назад.
- [ ] Не считать зелёный CI доказательством реальной доставки webhook или факта изменения настроек Prodamus.

Важно: **не обновлять** `PRODAMUS_SIGN_SECRET` и webhook URL без согласования с уже оплачивающими клиентами; иначе существующие уведомления могут перестать подтверждаться.
