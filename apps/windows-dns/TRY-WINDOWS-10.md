# мнебыDNS — установка и проверка Windows-клиента

Это неподписанная сборка для проверки на Windows 10 22H2. Архив должен содержать в одной папке:

- mnebydns-windows.exe — GUI и трей;
- mnebydns-setup.exe — UAC helper и управление службой;
- mnebydns-health-service.exe — фоновая Windows-служба; при установке из неё создаётся отдельный защищённый `mnebydns-recovery-service.exe`;
- START-HERE.md и SHA256.txt.

## Первый запуск

1. Распакуйте ZIP целиком. **Запускайте `mnebydns-windows.exe`**, а не вспомогательный `mnebydns-setup.exe` (он вызывается приложением с правами администратора).
2. На главной — только статус и кнопка **«Включить» / «Выключить»**.
3. Если адрес ещё не задан, в «Настройках» введите персональное имя DoT без `https://` и нажмите **«Сохранить»**. Сохранение **не включает DNS Windows**. При первой установке двух служб Windows один раз запросит UAC.
4. Вернитесь на главную и нажмите **«Включить»**. При обычном включении, выключении и восстановлении повторный UAC не требуется.
5. После подтверждения работы службы главная покажет **«Включён»**, а кнопка — **«Выключить»**. При отключении служба проверяет восстановление исходных DNS.
6. При повторном запуске сохранённый DoT-профиль используется без нового ввода. Для смены сервера сначала выключите DNS на главной, сохраните новое имя в «Настройках» и снова включите.

Сохранённый адрес отображается в настройках как «Адрес сохранён» и не требует повторного ввода. Кнопка «Проверить» выполняет защищённую проверку DoT через установленную службу, не раскрывая персональный hostname. Проверки адаптеров и восстановление DNS остаются в раскрываемых технических разделах.

**Исправление ошибки VCRUNTIME140.dll:** новый архив собирается со статическим C runtime и проходит проверку импортов EXE. Если вы используете *старый* архив и видите сообщение об отсутствующем `VCRUNTIME140.dll`, установите официальный [Microsoft Visual C++ Redistributable x64](https://aka.ms/vc14/vc_redist.x64.exe), но предпочтительнее использовать новую сборку. Не скачивайте отдельные DLL с посторонних сайтов.

Клиент автоматически обрабатывает активные Wi-Fi/Ethernet интерфейсы IPv4/IPv6. Туннельные и явно виртуальные интерфейсы он не изменяет, чтобы не нарушить работу VPN. Вручную выбирать адаптеры или вводить hostname в PowerShell не требуется.

## Проверка

В PowerShell можно независимо посмотреть текущие адреса DNS:

~~~powershell
Get-DnsClientServerAddress |
  Sort-Object InterfaceIndex, AddressFamily |
  Format-Table InterfaceAlias, AddressFamily, ServerAddresses -AutoSize
~~~

На активных интерфейсах, управляемых клиентом, ожидаются 127.0.0.1 для IPv4 и ::1 для IPv6. Проверить локальный resolver:

~~~powershell
Resolve-DnsName example.com -Server 127.0.0.1
Resolve-DnsName example.com -Server ::1
~~~

Проверьте открытие браузера, YouTube, Telegram, нужных сервисов и работу при переключении Wi-Fi/мобильной точки доступа/VPN.

## Выключение и восстановление

На главной нажмите «Выключить», а при ошибке — «Восстановить DNS». При отказе основной службы приложение обращается к независимо установленной `MnebyDnsRecovery` без нового UAC. В настройках также есть «Восстановить исходные настройки». Служба возвращает для каждого интерфейса его прежний режим и DNS-адреса: статические — к исходному списку, автоматические — обратно к DHCP/RA. После проверки backup удаляется.

Если GUI не открывается, запустите PowerShell от имени администратора в папке с архивом:

~~~powershell
$setup = (Resolve-Path .\mnebydns-setup.exe).Path
$disable = Start-Process -FilePath $setup -ArgumentList 'disable' -Wait -PassThru
$disable.ExitCode
$status = Start-Process -FilePath $setup -ArgumentList 'status' -Wait -PassThru
$status.ExitCode
Get-Service MnebyDnsHealth
Get-DnsClientServerAddress
~~~

У вспомогательного EXE нет видимого консольного окна; поэтому PowerShell должен явно дождаться его завершения через `Start-Process -Wait -PassThru`. Код выхода `0` подтверждает успех команды, но фактические DNS-адреса проверяются отдельно.

Не удаляйте %ProgramData%\mnebydns-controller-v1 вручную. Там находятся резервные настройки, необходимые для восстановления.

## Автоматическое восстановление при отказе DoT

Служба проверяет реальную передачу DNS через локальный DoT-прокси. После трёх
последовательных неуспешных проверок она отключает системный режим и пытается
вернуть исходные настройки IPv4/IPv6. При невозможности точного восстановления
защищённый журнал сохраняется, а приложение показывает ошибку. Пользователь
может запустить независимое восстановление без UAC. Если повреждены обе
системные службы, вмешательство администратора может быть необходимо;
автоматический обход безопасности Windows не предусмотрен.

Первое испытание лучше провести с доступом к альтернативному интернету.
Механизм проверен тестами на Windows-раннере, но **не проверен на вашем ПК**.

## Если DNS не выключается или служба не отвечает

Не удаляйте каталог `%ProgramData%\\mnebydns-controller-v1` и не стирайте `system-dns-*.json`: там сохранены прежние настройки адаптеров.

1. Запустите PowerShell **от имени администратора**. Проверьте `Get-Service MnebyDnsHealth`.
2. Если старая служба не может вернуть DNS, выполните `Set-Service MnebyDnsHealth -StartupType Disabled`, затем `Stop-Service MnebyDnsHealth -ErrorAction Continue` и снова `Get-Service MnebyDnsHealth`. **Пока статус не Stopped, не пытайтесь менять DNS вручную:** запущенная старая служба может перезаписать параметры. При зависании остановки после отключения автозапуска потребуется перезагрузка и повторная проверка статуса.
3. После остановки можно временно восстановить **автоматическое** получение DNS на своём реальном интерфейсе, например `Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ResetServerAddresses`. ВНИМАНИЕ: это не вернёт прежние статические DNS, если они использовались; защищённые снимки не удаляются.
4. Чтобы попробовать вернуть **именно сохранённые ранее параметры** (IPv4, IPv6, профиль), в новой программе откройте «Настройки» → «Аварийное восстановление из резервных настроек». Действие работает только если служба остановлена и оставляет непроверенные снимки на диске.
5. Переход со старой версии на новую: «Обновить установленную службу». Обновление запрещено, пока резервные DNS-настройки не восстановлены точно или конфигурация всё ещё активна. После обновления может потребоваться снова включить автозапуск службы через Windows SCM.

Для обычного включения/выключения с новой установленной службой новый запрос UAC не нужен. При первом сохранении персонального DoT и обновлении/ремонте системной службы UAC необходим.

## Ограничения и диагностика

- Если DoT upstream недоступен, клиент не переключается на plaintext DNS. Это может временно нарушить разрешение имён до восстановления соединения или выключения DNS-клиента.
- Приложения с собственным DoH/DoT и отдельные VPN NRPT/split-DNS политики могут использовать другой DNS. Программа НЕ гарантирует перехват абсолютно всех DNS-запросов, особенно при включённом VPN.
- DNS не меняет маршрут трафика и не заменяет VPN.
- Если IP DoT hostname изменился, выключите клиент и включите снова, чтобы обновить закреплённые upstream IP.
- На этапе пробного включения персональное DoT-имя временно передаётся повышенному setup-процессу в аргументах запуска Windows; другие процессы с соответствующими правами могут прочитать их. Используйте индивидуальный ключ без других учётных данных.
- Не отключайте SmartScreen или антивирус. WebView2 Runtime должен быть установлен.
- Перед запуском можно сверить SHA-256 из SHA256.txt. Не публикуйте персональный DoT hostname на скриншотах.
